# 大众 MEB（ID 系列）ICAS3 兼容说明

> 参考材料：`CarPlay协议栈完整分析报告.md`（VW MEB ICAS3，`ICAS3GP_CN4_VW_R4220L` /
> MUVersion 6422 / 软件 1.422.4 / Samsung Exynos Auto V9 / Apple CarPlay 插件 320.17.7 +
> iAP2 3.0）与 `iap2_messages.csv`（同一固件反汇编出的 74 条 `send*` 消息 ID 表）。
>
> 本文回答两件事：**①「默认链接方式」要不要按这份报告改；②新增的「大众 ID」档改了什么、
> 哪些还没验证。**

## 一、结论先说

| 问题 | 结论 |
| --- | --- |
| 默认方式与这份报告有冲突吗 | **没有实质冲突**。逐条核对 10 项，9 项本来就对得上（见第二节） |
| 那有一处要改吗 | 有，**一处**：报告要求识别阶段双向（车机要收到手机的 `0x1D01`），而我们从不发 |
| 改了会影响现有车机吗 | 不会。补发识别帧**只在大众 ID 档**打开，默认档一个字节都不动 |
| 消息目录要动吗 | 要，纯日志可读性：按 CSV 补了 40+ 条命名（此前全是 `0x####`） |
| 画质/帧率要按报告调吗 | **不要**。ICAS3 自己会报画布与上限，硬编码反而错（见第二节第 6 条） |

## 二、默认方式逐条核对（改代码前必读，避免下次又改回去）

| # | 项目 | 报告（ICAS3 实证） | 本仓库现状 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 链路帧头 | 9 字节；偏移 8 是头校验和；**报告把偏移 6 标成 SessionID、7 标成 Reserved** | `HEADER_BYTES=9`；偏移 6 = **ack**、7 = sessionId、8 = 校验和 | **不改**。两者字节布局一致，只是报告第 6/7 的字段名疑似错位：它举的例子 `FF 5A 00 0B 40 00 01 00 XX`（ctrl=0x40 ACK、ack=1、session=0）与我们的读法完全吻合。按报告的标注去读会把确认号当会话号，**重传/ACK 立刻报废**——这是本仓库在奥迪 MIB3 与 DiPlay 上逐帧验证过的格式 |
| 2 | 消息体结构 | `u16 msgID + u16 groupLength + (u16 参数长 + u16 参数ID + 值)` | `Iap2Csm` 一字不差 | 不改 |
| 3 | 视频载荷 | **iPhone 发 AVCC（4 字节长度前缀），车机做 AVCC→AnnexB** | `sendFrameFromNals` 每 NAL 先写 4 字节大端长度 | 不改，**且绝不能改成 Annex-B 起始码**——那会让车机的转换函数把数据啃坏 |
| 4 | 视频帧头 | 128 字节，`bodySize` 含 16B Poly1305 tag | 128 字节 + `TAG_SIZE=16` | 不改 |
| 5 | 音频 | 主音频 `AAC-ELD/48000/2`，但**同时声明** `AAC-LC/48000/2` 与多档 PCM | 编码器只有 AAC-LC / PCM，按车机 `audioFormats` 能力协商选档 | 不改。**已知限制**：用不上 ELD；若某台 ICAS3 的 media 档只声明 ELD，会退到 PCM（仍能出声，延迟略高） |
| 6 | 分辨率 / 帧率 | CarPlay 画布 **1264×640**（面板 2240×1260 由 HMI 缩放）；`maxFPS` 由 HMI 配置、报告未给值 | 一律跟随 `/info displays[]`（`widthPixels`/`heightPixels`/`maxFPS`） | 不改。**大众档刻意不加 30fps 兜底**：没有证据说 MEB 只能 30，硬压只会让能跑 60 的车机降级 |
| 7 | 无线凭据 | 车机会**自己下发** `0x5703`；另有 `0x5700` 反向索要手机的 Wi-Fi 信息 | 发 `0x5702`，1 秒无应答就**并行**发 `0x4300`；收到 `0x5703` 即绑 WiFi | 不改。这条并行兜底是老大众实测的救命绳（2026-10-28：`0x5702` 后静默 13 秒、17 秒拆链） |
| 8 | CarPlay 控制通道 | 车机反连手机的 `_carplay-ctrl._tcp`，发 `GET /ctrl-int/1/<command>`（`requestUI` 等） | `CarPlayCtrlAdvertiser` 广播该服务，任意 `GET /ctrl-int/*` 回 200 | 不改 |
| 9 | `0x4301` 方向 | 车机（accessory）→ 手机 | 我们**收** `0x4301`（`handleLateStartSession`） | 不改 |
| 10 | 识别 `0x1D01` | 手机也要发自己的识别帧，**含本方会发/可收的消息位图**；收不到车机就不发 `0x4301` | 我们只发 `0x1D00`、收车机的 `0x1D01`、回 `0x1D02`，**从不发自己的 0x1D01** | **唯一实质缺口** → 大众档补发（第三节） |

一句话总结：**奥迪（Delphi）、别克（SAIC-GM/Cinemo）、老大众（探歌 MQB）都容忍「不发识别帧」，所以这个缺口一直没暴露；ICAS3 是苹果原厂栈，很可能不容忍。**

## 三、新增档位：`大众 ID（MEB ICAS3）`

`ConnectionProfile.VW_MEB`（id `vw_meb`），在「连接配置」下拉框里选。

**唯一行为改动**：`sendsDeviceIdentification = true` —— 在 `0x1D02` 之后补发我方 `0x1D01`。

帧内容（`iap2/DeviceIdentification.kt`，纯函数可单测）：

| paramID | 内容 | 取值 |
| --- | --- | --- |
| 0 | 名称 | 本机蓝牙名（真 iPhone 就是「xxx 的 iPhone」） |
| 1 | 型号 | `iPhone14,5`（车机只用它决定 HMI 图标） |
| 2 | 制造商 | `Apple Inc.` |
| 6 | 本方**会发**的消息 | 19 条（识别、CarPlay 可用性、`0x5702`、问候组、NowPlaying、MFi、EA 会话） |
| 7 | 本方**可收**的消息 | 25 条（`0x4301`、`0x5703`、`0x6800/6802`、MFi、车机订阅组、EA 状态） |
| 10/11/12 | EAP 协议组件 | **留空**（见第四节） |

两张位图在写出前**升序排序**，同一份清单永远产生同一串字节，便于逐字节对比。

### 为什么不做「自动识别」

ICAS3 的 `0x1D01` 身份串（name/model/manufacturer）**没有任何实测样本**：报告只写了
「参数包括名称/型号/制造商」，没给字面量。凭猜测做 AUTO 判定，命中即误伤——这与
「别克大连屏」档当初的处理一致（型号未知时只能靠人显式指定）。**有了一次真车日志后**，
把标记加进 `ReceiverProfile.variantOf` 或一个新的 `VwIdentity`，就能让 AUTO 认出来。

### 与老大众（MQB / 探歌那类）不是一套东西

| | 老大众（MQB，如探歌 23 款） | 大众 MEB（ID 系列，ICAS3） |
| --- | --- | --- |
| CarPlay 实现 | 车厂/供应商自研栈 | **苹果原厂** `AppleCarPlay_CommunicationPlugin 320.17.7` + `libiAP2Service-3.0.so` |
| Wi-Fi | 双频 `VW WLAN` / `VW WLAN_5GHz`，只认 `0x5703` 下发的那条 | 自建 5GHz AP `wlap5`（10.173.189.1/24，自带 DHCP） |
| 实测现状 | 已跑通（自动入网 + 邀请 + 推流 3 分钟） | **未验证** |
| 本文档的档位 | 不需要（走默认） | 需要（补识别帧） |

所以：**别因为「大众」两个字就把探歌的结论套到 ID 上，反之亦然。**

## 四、未验证项与上车核对步骤

一次真车连接，日志里按顺序找这四行（`下载/CarPToCarL/CarPToCarL-log-*.txt`）：

```
BT-C: 连接配置=大众 ID（MEB ICAS3）——补发我方识别帧…
iap2 0x1d01 车机身份 name=… model=… manufacturer=…     ← 车机身份（能填 AUTO 判定）
iap2 tx=0x1d01 我方识别 0x1D01 name=… 会发=19 条 可收=25 条 EAP=0 条
iap2 rx=0x1d02 车机接受我方识别                          ← 或 rx=0x1d03（被拒）
```

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| 没有 `tx=0x1d01` 那行 | 档位没生效 | 确认下拉框选的是「大众 ID（MEB ICAS3）」，且改动在**下一次连接**生效 |
| `rx=0x1d03 车机拒绝了我方识别` | 声明的位图/字段它不认 | 把 `0x1d03` 的 body 十六进制作证据；先怀疑「缺 EAP 协议名」，其次怀疑位图里有它认为非法的项 |
| 有 `tx=0x1d01` 但车机**既不回 0x1d02 也不回 0x1d03** | 车机忽略了这一帧（不认这个消息 ID 的用法） | 说明「补识别帧」不是 ICAS3 的症结，回到 `docs/PROTOCOL-NOTES.md` 的邀请/配对路径继续查 |
| 识别通过但 `0x4301` 不来 | 卡在后面的阶段（邀请、ctrl-int、MFi） | 看 `CTRL:` 与 `AIRPLAY:` 前缀的日志；此时与本档位无关了 |
| `/info` 报的画布不是 1264×640 | 该固件 HMI 配置不同 | **不要改代码**，跟随车机即可；但值得记进本文档 |

**回退**：改选「通用（标准）」就完全回到 1.2.16 的行为，不需卸载重装。

## 五、已知缺口（**有证据再补，别猜**）

1. **EAP 协议名**：报告说识别帧里要带「CarPlay 外部配件协议名」，但两份材料都没给字面量
   （ICAS3 固件里只有车机侧的 `com.audi.cpp.eadata0/1`、`de.audi.mmicconnectdatatransfer`）。
   凭空写一个协议名比不写更糟：车机会判「声称支持但握手对不上」。
   需要一次**真 iPhone 的 `0x1D01` 抓包**（USB 抓包或 sysdiagnose），填进
   `DeviceIdentification.Spec.eapProtocols` 即可，代码位置已留好（参数组 10/11/12）。
2. **建链方向**：报告说「车机作为 accessory 连 iPhone 的 iAP2 服务」，老大众日志也说
   「它只在自己愿意时发起」。但本仓库两条路径本来就同时开着（`…caff` 主动拨号 +
   `…cafe` 被动监听），且对「连上 0.5 秒被关」已有退避（3s→10s→20s），
   **没有再单独做一个「大众被动档」**——两个证据都指向「被动兜底已够」，多一个档只会增加选择负担。
3. **AAC-ELD 编码**：ICAS3 的主音频是 ELD，我们只能发 AAC-LC。要补需要换编码器，
   与「链接方式」无关，单独立项。
4. **车速分心限制**：ICAS3 会订阅车速并据此下发 `setLimitedUI`。我们不做行车禁用，
   等于让车机以为可以一直全功能——首版可接受，属于**合规风险而非连接问题**，记在这里。
5. **WiFi 隧道那条链路的识别帧没补**：AirPlay 会话建立后，iAP2 会迁到 WiFi 隧道
   （`VirtualIap2Link`），那里是**另一次**完整的 `0x1D00 → 0x1D01 → 0x1D02`，
   同样是「只回 0x1D02、不发自己的 0x1D01」。本次只改了蓝牙 bring-up 阶段：
   先把连接跑通，再决定要不要动隧道（那里的代码服务着已跑通的 MIB3/DiPlay，
   改错的代价比蓝牙阶段大得多）。判断依据：如果蓝牙阶段识别通过、`0x4301` 也来了，
   但 AirPlay 起来后**控制通道**（触摸/媒体键）不通，就轮到这一条了。

## 六、顺带补全的消息目录

按 `iap2_messages.csv` 把 40+ 条消息补了名字（`Iap2MessageIds`），**不改任何行为**，
只让能力清单日志从 `0x4c00` 变成 `StartMediaLibraryInformation`：

- `0x10DA/DC/DD` 目的地信息 · `0x1D05/06` 识别取消/更新 · `0x4302` `0x4301` 的状态回执（编号推断）
- `0x415A–0x4161` 通话控制（接听/挂断/互换/合并/保持/静音/DTMF）
- `0x4C00–0x4C09` 媒体库浏览与点播 · `0x4E01/03/05` 蓝牙组件与连接状态
- `0x5003` NowPlaying 上报 · `0x5203` 停止导航引导
- `0x5400–0x5404` 辅助触控 · `0x5601–0x5613` VoiceOver 全套
- `0x5700` 反向索要 Wi-Fi 信息 · `0xAD00/02/03` App 发现
- `0xAE02/03` 停止电源更新/电源状态 · `0xDA00/02` USB 音频

补完目录后，`Iap2CapabilityReportTest` 里两条「拿 `0xAD00` 当未知 ID」的用例会失效，
已改成真正未知的 `0x7A01`——这类测试要挑**目录外的号**，别挑「暂时没命名」的号。
