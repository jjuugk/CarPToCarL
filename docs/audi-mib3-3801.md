# 奥迪 MIB3（3801）专版连接优化

> 分支：`switch-pool`（切换连接池，原名 `bieke`）　版本：1.2.11-switchpool　2026-11-02
>
> 参考实现：[`xi_zhu/AuDiCar`（CarTolife+，MIT）](https://cnb.cool/xi_zhu/AuDiCar)
> ——该项目自本项目分叉后收敛为「奥迪 MIB3 3801 专属」实现，本文只取其
> **连接时序**部分，其余（画质、通话、封面、编码器）不涉及。

## 一、为什么要「专版」

同一个品牌的不同固件，对连接握手两个关键参数的偏好**完全相反**：

| 车机 | MFi 20B | MFi 32B | 依据 |
|---|---|---|---|
| 奥迪 MIB3 **3801** | **秒答**（390–430ms） | ACK 挑战帧后**整段静默**，会话变僵尸 | 对方 3801 实车（4 次握手样本） |
| 奥迪 **MMI 0000**（旧） | **静默 6.0 秒** | 0.64 秒回签名 | 本项目 `docs/PROTOCOL-NOTES.md` §9 |

通用参数只能折中：基线 `32 → 20 → 16` 是为 DiPlay 测试台（只认精确 32B）让的路，
奥迪每次连接都要先在 32B 上赌一次「会不会变僵尸」。专版才有意义。

## 二、怎么识别（不写死车型号与固件版本）

判定入口：`ReceiverProfile.variantOf(identityText)`，纯函数，可单测。

输入是 0x1D01 的 `name + model + manufacturer`，实测奥迪 MIB3 为
`GeXu-Audi / AUDI 3260 / DELPHI`。

```
含 "audi"                  → AUDI_MIB3
含 "delphi" 且含 "mib"      → AUDI_MIB3     // 个别车机 model 只报 MIB3
其余                        → GENERIC
```

**刻意不按车型号（3260 / 3874）或固件版本（3801）硬编码**：

- 固件升级不该让专版失效，同代车机的连接时序是一致的；
- 固件字符串（`CL37_MIB3H_AU_AS_G4x_2302700PROD`）里**读不出 3801/3874** 这种版本号，
  按它分流等于靠猜。

判据也刻意不放宽：只凭 `delphi` 会命中别的车厂；只凭 `mib` 会命中 HARMAN 的 MIB2
（Porsche / 旧款 Audi），而那类车机认 32B、与本专版时序相反。

### 判不出来时：下拉框里的「奥迪 MIB3（3801 强制）」

自动判定依赖车厂把身份字段写对。遇到写私有串、或 `manufacturer` 不是 DELPHI 的固件，
判据会落到 `GENERIC`——而那时用户手里**一个开关都没有**。这是 1.2.11 加这个人
工档位的唯一理由（与「别克 大连屏」档同一个思路：型号未知时只能靠人指定）。

`ConnectionProfile.AUDI_MIB3`（id `audi_mib3`）选中即认：

| 行为 | 说明 |
|---|---|
| 忽略 0x1D01 身份 | 直接按专版走 `20→16` + 20B 窗口 1.5s + `0x5703` 五轮 |
| `allowsB233 = false` | 排除别克流程。两个档位的 `0x4300` 报文体与 MFi 硬要求正好相反，不关的话「选了奥迪却连了台名字像别克的设备」会被 `looksLikeBuick` 拉进 B233 |
| 经端点带到隧道 | `CarPlayEndpoint.forceAudiMib3` → `VirtualIap2Link`。那里是**另一次** MFi，不显式带过去就会退回通用基线 `20/32/16`，把 3801 又挂成僵尸 |

选错档也不会打死旧车机：`MfiLengthMemory` 会把该车机成功过的档位**强制排第一**，
只认 32B 的 MMI 0000 连过一次之后就自动纠正，最坏是冷启动首次多等几秒。

日志会区分来源，排查时一眼能看出是谁定的：

```
iap2 车机专版：奥迪 MIB3 专版（下拉框指定，忽略身份判定）（身份 ...）
IAPLINK: 隧道 MFi 基线 奥迪专版 20/16（下拉框指定奥迪档）（身份 ...）
```

## 三、改了什么

### 1. MFi 挑战档位：去掉 32B

| | 基线顺序 | 20B 窗口 |
|---|---|---|
| 通用 | 32 → 20 → 16 | 6.0s |
| 别克 B233 | 32（硬要求，不回落） | 3.0s |
| **奥迪 MIB3 专版** | **20 → 16** | **1.5s** |

代码：`Iap2SenderSession.AUDI_MFI_LENGTHS` / `AUDI_MFI_WINDOW_20_MS`（蓝牙链路），
`VirtualIap2Link.AUDI_TUNNEL_MFI_BASELINE` / `AUDI_TUNNEL_MFI_WINDOW_20_MS`（隧道链路）。

两处都要改，因为同一次连接会先后走两条链路：蓝牙 RFCOMM 控制会话 + AirPlay 之上的
虚拟 iAP2（事件通道 / type-130 隧道）。两条链路的认证后端可能不同。

**旧固件不会被这条改动打死**：`MfiLengthMemory` 把该车机**成功过的档位强制排第一**，
哪怕专版基线里没有 32。MMI 0000 在本项目历史版本上已经连过很多次，记忆里存着
「32B 成功」→ 下次仍先试 32B。冷启动第一次多花 1.5 + 3 = 4.5 秒，之后直达。

### 2. 0x5703 交接：3 秒 × 5 轮重试

旧实现：发一次 `0x5702`，1 秒没回就并行发 `0x4300`，然后一直等 `deadline`。

新实现（仅对真车系 / `legacyCar`）：

```
发 0x5702 → 等 3.0s
  没回 → 发 0x4300（MMI 0000 依赖它补发 0x4301，保留）
       → 每 3.0s 补发一对 0x4E0E + 0x5702，最多 5 轮 / 15 秒
```

依据：真 iPhone sysdiagnose（`docs/iphone-ref-1015.md` §3.1）——交接卡住时 iPhone
以 3 秒为间隔连发 `0x4E0E + 0x5702`，实测时间点 9.87 / 12.96 / 15.97 / 18.99 / 21.99 秒；
而顺利的那一次一次都没重试。

两个坑都避开了：

- **首轮不能直接等到总 `deadline`**：那样重试逻辑一次都进不去（对方 2026-10-30 日志的
  真实死法：发出 0x5702 后阻塞到 30s 总超时，直接抛「iAP2 链路协商超时」）。
- **不额外 sleep**：轮间隔就是「等满一个 3 秒窗口」。旧写法 `sleep(3s) + 等 3s`
  等于每轮 6 秒，5 轮预算只跑得动 2 轮。

别克 B233 不走这条：它对催问是「收下但不 ACK」，多催只会拖死握手（已在更外层排除）。

### 3. 重传超时不改，沿用对端声明

对方把 `retransmissionTimeoutMillis` 默认值从 4000 改成 3000（依据 MIB3 3874 的
`extdevconfig.json`）。本项目**已经有更强的机制**：`Iap2LinkEngine` 会采纳对端在
SYN 里声明的 RTO 当本地节拍（`peerRetransmissionTimeoutMillis`），比写死 3000 更准。
因此本项不改。

## 四、刻意不做的事

| 项 | 为什么不抄 |
|---|---|
| MFi 挑战固定单档、连记忆一起去掉 | 我们还要兼容别克 B233（硬要求 32B）与 DiPlay 测试台，记忆是按车机隔离的，留着更安全 |
| 默认画布写死 1412×654 | 本项目有 `CarCanvasMemory`，按车机蓝牙地址记忆 SETUP 画布，换车自适应；写死反而绑定单车型 |
| 撤掉 0x4155 通话状态主动推送 | 那是通话 UI 的取舍，与连接建立无关；本项目在别克上依赖它 |
| TEARDOWN 补 `type` | 本项目没有「音频显式 TEARDOWN」这条路径（对方 1.0.25 自加的功能），无对应改动点 |
| 码率 / 麦克风 / 封面临时文件 | 属画质与媒体面，不是连接协议 |

## 五、上车后看这几行

| 日志 | 含义 |
|---|---|
| `iap2 车机专版：奥迪 MIB3 专版（MFi 20B 单档 + 0x5703 五轮交接重试）` | 专版命中 |
| `iap2 车机专版：通用参数` | 没识别成奥迪，走通用（不影响原有行为） |
| `iap2 tx=0xaa02 challenge=20B（第 1 次，窗口 1500ms）` | 20B 单档、窗口已压到 1.5s |
| `iap2 0x5703 第 N 轮未到——补发 0x4e0e + 0x5702` | 交接卡住，正在按真机节奏重试 |
| `IAPLINK: 隧道 MFi 基线 奥迪专版 20/16` | 隧道链路也走了专版 |

判错的兜底：如果日志显示「通用参数」但车确实是奥迪，看同一行括号里的身份原文
——大概率是 0x1D01 的 model/manufacturer 里没有 `audi`/`delphi` 字样，
把该车的实际身份补进 `ReceiverProfile.variantOf` 的判据即可。

## 六、风险与验证状态

- **单测覆盖**：专版判定（含 HARMAN MIB2 不应误判）、基线去 32、记忆兜底旧固件。
- **未实车验证**：本版参数依据来自对方 3801 实车与我们的旧日志，**本机尚未跑过
  3801 实车**。首连时重点看第 5 节那四行日志。
- **回退**：若奥迪上反而更慢，把 `Iap2SenderSession.AUDI_MFI_LENGTHS` 改回
  `listOf(20, 32, 16)` 并把 `AUDI_MFI_WINDOW_20_MS` 调回 `6_000L`，
  或在 `variantOf` 里直接返回 `GENERIC`（一行回退，不影响别克）。
