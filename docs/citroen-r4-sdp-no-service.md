## 2. 判断：卡在 RFCOMM 建链，不是协议层

- 失败发生在 `…caff`（配件端 iAP2 服务）的 RFCOMM 建链，**还没进入 iAP2**：
  没有 `0x1d00/0x1d01`、没有 MFi、没有 `0x4300`。
- **180 毫秒**就返回失败——这不是超时，是 `createRfcommSocketToServiceRecord()` 在
  SDP 记录里查不到 `…caff`，本地直接抛异常。也就是说：**车机此刻没有对外宣告无线
  CarPlay 的 iAP2 服务**。
- 与凯迪拉克那台形成对照：那台能建链、能过 MFi、只是不发 `0x4301`；这台连服务都看不到，
  属于更靠前的一层。

## 3. 为什么车机不宣告该服务（按可能性排序）

1. **该车型/配置只支持有线 CarPlay**。Stellantis 车机（R4/NAC/IVI）不少版本只有 USB
   CarPlay，无线需要特定年款或选装。若如此，蓝牙这条路无解——`…caff` 永远不会出现。
2. **车机没开无线 CarPlay**：需要在中控「手机投屏 / Apple CarPlay」里启用，或先把车机
   里已连接的其它手机断开（一台车机同一时刻只服务一台）。
3. **必须先 USB 连一次**完成无线配对（部分 PSA 车型的既有流程）。
4. 我们「先断开 HFP/A2DP 再连 iAP2」的顺序在自己这边制造了变量：断开瞬间车机可能正
   退出可发现/可连接状态。180ms 的失败早得可疑。

## 4. 顺带暴露的两个产品问题（已在 1.0.8 修）

### 4.1 软回退后不再过 SDP 闸门 → 把耳机/键盘/音箱全试一遍

`candidateDevices()` 在软回退时返回**所有已配对设备**，而闸门条件是
`targetProvider() == null`——目标只是「降级」并没有被清空，于是闸门被整体跳过。
日志里 18:54:28 刚判过「银河A7 没有 iAP2 服务」，18:55:54 又在连它；连蓝牙键盘
（AB Shutter3）、音箱（BT-SPEAKER）也照试，**每轮都会断掉它们的音频**，还拖慢重试节奏。

**改法**：闸门条件加上 `|| BtSessionGate.targetSoftFallback`——回退态按「自动模式」处理。

### 4.2 「连接失败」不带原因，判不出是哪一种故障

原日志只有 `连接 X 失败（车机未就绪或不在无线配对窗口）`，而实际情况至少三种：
`Service discovery failed`（SDP 无该服务）、`Connection refused`（有服务被拒）、
`read failed / timeout`（车机卡住）。三者处置完全不同。

**改法**：`tryConnect()` 记录 `lastConnectError`（socket 建立失败与 `connect()` 失败分别标注），
失败日志带上原始原因；原因里出现 discovery/service 时追加一句
「车机 SDP 里没有无线 CarPlay 的 iAP2 服务（未开无线 CarPlay / 该车型仅支持有线）」。

## 5. 还改了连接顺序：先试，再断配置文件

原流程对所有目标都先断 HFP/A2DP 再连 `…caff`（源自奥迪 MIB3 的「已连接状态不开放窗口」）。
但这台雪铁龙的情况可能正相反——**断开动作本身**让它退出准备状态。

现在改成两步：

1. 保持现有配置文件直连一次；
2. 失败后才断开 HFP/A2DP 重试一次（奥迪那类机型在第二步成功）。

对奥迪没有损失（多一次几百毫秒的失败尝试），对「需要保持连接」的车机则可能直接救回来。

## 6. 下次复测看这三行

```
BT-C: 连接 My Citroen … 失败（建立 socket 失败：Service discovery failed）——车机 SDP 里没有无线 CarPlay 的 iAP2 服务（…）
BT-C: 连接 My Citroen … 失败（Connection refused / read failed …）——车机未就绪或不在无线配对窗口
BT-C: ✓ 已连入 My Citroen … 的无线 iAP2 服务（RFCOMM 建立）
```

- 第一行 → 该车机确实没有无线 CarPlay 的 iAP2 服务：先确认车型是否支持无线（车机菜单里
  能否看到「无线 CarPlay」），必要时插 USB 走有线，或先 USB 连一次再试无线；
- 第二行 → 车机在，但没开门：去中控里手动选中本机 / 断开其它手机后重试；
- 第三行 → 进到 iAP2 了，后面按 `gm-cinemo-4301-deadlock.md` 的判读继续。
