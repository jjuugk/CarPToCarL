# 法律风险与商业化注意事项

> 本文是维护者自己做的风险梳理，**不是法律意见**，也不构成对任何具体行为的合法性背书。
> 真到商业化那一步，请找做知识产权 / 涉外协议的律师过一遍。
> 最后更新：2026-10-25。

## 0. 一句话结论

**开源这件事本身风险可控；把「软件本身」当商品卖，性质会变**——从「被要求下架」升级为
「可主张赔偿」。收费只做「赞助 / 技术支持」，不要卖 APK 或订阅。

## 1. 这个项目在做什么（决定风险落在哪）

| 行为 | 涉及的第三方权利 |
|---|---|
| 实现 iAP2（0x1d00/0x1d01/0xaa00~0xaa05/0x4e0d/0x5702/0x4301…） | Apple 私有协议 + MFi 项目条款 + 相关专利 |
| 响应 MFi 挑战（`0xaa05 authentication-succeeded` 自报成功、按车机记忆选 20/32/16B） | 认证机制 / 技术措施 |
| 实现 AirPlay（pair-setup / pair-verify / SETUP / RTP / ChaCha20） | Apple 私有协议 + 专利 |
| 劫持本机 CarLife+ 引擎（7240 / 9340 端口、98386 / 98311 / 98316 等消息号） | 百度著作权 + 反不正当竞争 |
| 设备名冒充车机（如 `Audi_MMI_xxxx`）、使用车型/品牌名 | 商标权 |
| 读取通知使用权（媒体信息）、AudioPlaybackCapture（录音）、蓝牙、位置 | 个人信息保护（PIPL） |

自研代码本身没问题（仓库里没有反编译产物、没有厂商 SDK、没有真机凭据，见第 5 节）；
风险来自**上面这些被实现的协议**，而不是「你写了多少行 Kotlin」。

## 2. 风险分层

| 风险 | 开源 | 收费 | 说明 |
|---|---|---|---|
| **MFi / iAP2 授权** | 🟠 中 | 🔴 高 | iAP2 属 MFi 体系内的私有协议。开源通常先收到 DMCA / 律师函要求下架；收费后可主张商业损害 |
| **规避技术措施** | 🟠 中 | 🔴 高 | 伪造认证应答属于「绕过认证机制」，与是否复制代码无关。中：《著作权法》第 49 条；美：DMCA §1201 |
| **商标** | 🟢 低 | 🟠 中 | 文档里描述性引用风险低；**产品名 / 商店描述 / 推广文案**里出现「支持 CarPlay」「奥迪专用」风险立刻升高。设备名冒充更是直接的商标性使用 |
| **百度 CarLife** | 🟠 中 | 🔴 高 | 劫持本机 App 的本地端口 + 反编译所得协议。个人研究难追责，商业分发是明确靶子（《反不正当竞争法》第 2 条、第 12 条） |
| **专利** | 🟡 低-中 | 🟠 中 | AirPlay / CarPlay 有专利池；收费给赔偿提供基数 |
| **开源许可证** | 🟢 低 | 🟢 低 | MIT 允许收费。风险只在「是否把 GPL 参考项目翻写进来」：行为/格式复刻一般可以，逐行翻译不行 |
| **隐私合规** | 🟡 低-中 | 🔴 高 | 通知使用权 + 录音 + 蓝牙/位置；收费即商用，PIPL 的告知同意、隐私政策、**App 备案**必须落地 |
| **经营主体 / 税务** | — | 🟠 中 | 个人长期收款易被认定为经营行为：个体户/公司、发票、《电子商务法》登记 |
| **密码合规** | 🟢 低 | 🟡 低-中 | 用到 ChaCha20 / X25519 / HKDF。《密码法》+《商用密码管理条例》对「商用」有要求；开源非商用一般不触发 |
| **产品 / 安全责任** | 🟢 低 | 🟠 中 | 车机显示涉及驾驶分心；收费形成消费合同，出事故可能被追责（《消费者权益保护法》质量担保） |

**免责声明不能免疫。** 它只影响「用户自担风险」的过错分配，对 Apple / 百度的侵权主张
没有任何作用。DISCLAIMER.md 写得再好，也不能替代授权。

## 3. 「支持收费」的做法排序

| 做法 | 风险 | 说明 |
|---|---|---|
| 打赏 / 赞助（爱发电、GitHub Sponsors） | 🟢 最低 | 纯赠与，不是软件销售 |
| 卖技术支持 / 部署咨询 | 🟢 低 | 独立服务合同，交付人时，不含软件许可、不承诺兼容性 |
| 双授权（MIT 免费 + 商业支持合同） | 🟡 低-中 | 同一份代码，不锁功能 |
| 卖 APK / 订阅制 | 🔴 高 | 变成商品：上表红色项全部激活，还要加备案、隐私政策、售后、退款 |
| 宣传「CarPlay 无线适配」「某车型专用」 | 🔴 高 | 商标 + 虚假宣传（《反不正当竞争法》第 8 条） |

## 4. 商业化前的三件套（缺一不可）

1. **经营主体**：个体工商户或公司；能开票、能签服务合同。
2. **App 备案**：工信部要求，国内分发必须；无备案商店会下架。
3. **隐私政策 + 个人信息清单**：通知使用权、录音、蓝牙、位置逐项说明用途、最小必要、
   保存期限、撤回方式；首次启动明示同意。

## 5. 仓库现状（2026-10-25 审计）

已确认「可以开源」的几件事：

- **来源清晰**：本项目的协议层、密码学封装、蓝牙链路与工程骨架参考了
  [CarDeck](https://github.com/shaonialife/cardeck)（MIT，版权归其作者）。该项目由第三方
  独立开发，**与本项目非同作者**；按其 MIT 许可，版权与许可声明已保留在
  [NOTICE](../NOTICE) 第 0 节，不附加其它义务。
- 反编译产物、厂商 SDK、抓包原始文件全部不在版本库内
  （`.tools/`、`carlife-ref/`、`*.dex`、`*.jks` 均在 `.gitignore`）；
- 真实热点密码只存在于运行时内存，日志里一律 `psk=***`；
- 测试与文档里的车机名 / MAC 已脱敏为 `Audi_MMI_0000` / `AA:BB:CC:DD:EE:FF` /
  `DESKTOP-XXXXXXX`；多个真实型号统一折叠成 `0000`，所以正文里出现同名的
  「Audi MMI 0000」可能指不同年款，靠上下文（日期 / 行为差异）区分；
- **历史提交已重写**（2026-10-25，首次推送到 GitHub 之前用 `filter-branch` 跑同一份脱敏脚本），
  旧提交里的原始车机名 / MAC 不会随 `git log` 一起公开；
- 依赖全部是 Apache-2.0 / MIT 系（AndroidX、Kotlin、BouncyCastle），无 GPL 传染；
  第三方声明见 [NOTICE](../NOTICE)，并已随二进制打进 APK 的 `assets/NOTICE.txt`。

仍需注意：

- `docs/` 里的实测记录包含协议细节与时间线，属于「研究记录」性质。保留可以，
  但**不要**附带任何抓包二进制、证书、密钥、车机固件。
- 不要在 issue / PR 里贴完整抓包或车机密钥；维护者回复时也不要转述私有文档原文。

## 6. 贡献与分发时该做的事

- PR 模板加一条勾选：「未包含反编译产物 / 厂商 SDK / 真实凭据」。
- 跑一遍仓库自带的守卫脚本，防止手滑提交：

  ```bash
  ./scripts/check-no-vendor-artifacts.sh      # 0 = 干净，1 = 命中禁止项（附清单）
  ```

  它检查：反编译产物与二进制、签名材料、`.tools/` 与参考实现目录、明文 psk / passphrase。

- 发布页只写「实验性互操作研究」，不写「支持某车型」「可替代原厂」。
- 收到下架 / 律师函：停止分发、保留证据、找律师，不要在公开渠道争论技术细节。
