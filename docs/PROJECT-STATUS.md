## 二、活跃风险与已知硬缺口（按优先级）

### P0 —— 影响可用性且尚无通用软件解

1. **厂商后台冻结（非 Doze）**
   - 观测：荣耀（冻结 7/19/25s）、一加（10s）、vivo Android 16 / iD9（28 分钟冻 16 次、最长 219s）。
   - 现状：已有心跳 ≥4000ms 判冻结 + 1.5s 复核 + 3/6/12/24s 重建与前台 `mediaPlayback` 服务，但「忽略电池优化」管不到厂商冻结，仍需产品层引导用户开启各品牌自启动/后台白名单。
2. **音频顿挫听感复测（`1.2.70`）与 BMW `controlPort 6011` 不监听（`1.2.83`）**
   - `1.2.70` 发包均匀性已由手机录音验证，但实车听感未复测；BMW MGU-81 日志显示 `6011` 同步包几乎全部被 ICMP 拒收，车机缺 RTP↔NTP 锚点时偶发卡顿需继续排查。

### P1 —— 特定车型 / 能力硬限制

3. **宝马 300 / iD9 无法建链**
   - 观测：12 次 iAP2 会话零 `0x4301`，5 次 mDNS 均无 `_airplay._tcp`，Wi-Fi 随后断开回 4G；需先确认车机热点是否启用 AP 隔离 / 屏蔽 mDNS。
4. **帧率与画质受厂商侧限制**
   - 荣耀虚拟屏默认 `20fps`（需用户手动改车联设置到 60），厂商 mix 层可能覆盖编码尺寸；手机侧必须保持「分辨率 = 默认」。
5. **非蓝牙/无 root 场景的通话音频与有线 USB**
   - `AudioPlaybackCapture` 不允许捕获 `USAGE_VOICE_COMMUNICATION`；有线 USB 受 Android USB gadget 权限限制（见 [`WIRED-CARPLAY-FEASIBILITY.md`](WIRED-CARPLAY-FEASIBILITY.md)）。

### P2 —— 工程债与后续方向

6. **协议模块化收尾**：`protocol/` 已完成媒体键、语音键、触摸、播放意图及 `VideoSink`/`AudioSink` 收口（详见 [`PROTOCOL-MODULES.md`](PROTOCOL-MODULES.md)）；`SessionController` 进一步瘦身待实车回归稳定后推进。
7. **接收端统计不可观测**：部分测试台（如 WinPlay）不回报 `statsDictionary`，车机侧丢帧/卡顿难以从手机侧直接定责。
8. **协议对齐专项**：例如仅声明 Opus 的 `101/default` 导航音频流（如 BMW iD8）、资源借用账本、以及非小米机型的导航引导数据源接入。
